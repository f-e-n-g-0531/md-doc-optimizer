# 逐目标检查清单（audit-checklist.md）

按目标逐条打勾；每条命中都应落到「文件:行号 + 证据」。无法确证的一律记为 NEEDS_HUMAN，不得脑补。

## 目标 A —— 去冗余

- [ ] 全文检索是否有同一说明出现两次及以上（含「简介里的简介」「节内重复」）。
- [ ] README 与 docs/ 是否互拷同一段（安装步骤、示例、FAQ）。
- [ ] 是否有同名同级标题（对照 markdownlint MD024）。
- [ ] 是否存在多个一级标题（MD025）而内容其实是单一主题。
- [ ] 同一 URL 是否多次出现且无需分开（可合并到一处/页脚引用）。
- [ ] 是否有口水词、套话：非常简单、只需、众所周知、轻松、快速上手、强大的、灵活的。
- [ ] 是否有冗余限定词叠加：可能/大概/基本上 + 或许；「完全彻底」类。
- [ ] 是否有同一段落的加粗+斜体双重强调，或长短两版并存。
- [ ] 是否有从未被使用的「未使用引用定义」，或同一标签的重复定义（remark-lint no-unused-definitions；预扫的 unused/duplicate-reference-definition）。
- [ ] 删除后是否破坏原有链接锚点或交叉引用（安全网检查）。

## 目标 B —— 删除过期 / 失效

- [ ] 是否有相对/绝对时间表述已过当前日期：目前、最近、近期、刚刚、去年、2023 年起、将于 X 上线。
- [ ] 指向的文件/目录/脚本/CI 工作流是否仍存在（逐条核对路径）。
- [ ] 命令/flag/env 是否仍可用（能跑则跑，跑不通记 run-failed）。
- [ ] 链接是否仍可达（lychee / markdown-link-check / 直接请求），锚点是否仍存在（GitHub 锚点保留 `_`；重复标题依次加 `-1`/`-2`；`<a name>` 等显式锚点也算）。
- [ ] 路径大小写是否与磁盘真实文件名逐段一致（Windows/macOS 检出时能打开，Linux/CI 上会 404；目录名同样要核对）。
- [ ] 本地图片（相对路径）是否仍存在；是否存在空链接目标（`[]()`）或未定义的引用标签（`[text][label]` 会渲染成字面文本）。
- [ ] 链接目标是否因**默认分支改名**（master→main）或**文件改名**（.js→.ts、目录迁移）而失效？404 后到仓库树确认当前路径，不臆测。
- [ ] 版本号 / 依赖 / API 端点 / 配置键是否已改名或删除（对照 package.json、CHANGELOG、发布记录）。
- [ ] TODO / FIXME / 待补充 / coming soon / TBD 是否早已完成（先排除测试夹具与设计草稿中的 WIP 注释）。
- [ ] 示例代码输出是否与当前可运行结果一致（mdoctest 比对输出；markdown-doctest 只验证不抛异常，不比对输出）。
- [ ] 描述的功能是否已下线/改名（如有疑问标 NEEDS_HUMAN）。

## 目标 C —— 修正与事实不符

- [ ] 参数名、默认值、返回结构、路径、版本号是否与代码/配置冲突。
- [ ] 示例代码/输出与可运行结果是否一致。
- [ ] 数字、时区、日期、大小写、拼写、术语、产品名是否错误。
- [ ] 链接文本是否与链接目标不匹配（文本写 A，链到 B）。
- [ ] 断言性结论是否有依据，或与权威来源冲突（无一例证 → 标 DUBIOUS）。
- [ ] 配额/限额/价格/兼容矩阵等易变数字是否可溯到权威来源。

## 反误报检查（判定「不该改」）

命中以上目标后，先用本节排除误报，避免把正常内容删掉：

- [ ] 目标文档是否由代码/脚本/schema 生成？先找生成器与发布脚本（`docs:*`、`prepublish`、CI 生成步骤），改源文件后重新生成，不手改产物。
- [ ] 目标文档是否被测试引用（test/、fixtures/）？夹具里的坏链接、命令、TODO 属内容本身，不改。
- [ ] 失效链接是否只是默认分支或文件改名？用仓库默认分支与当前文件列表核对后再改。
- [ ] 重复内容是否各自必要（多平台安装命令、不同场景示例、CLI help 同步）？
- [ ] 过时内容是否属历史记录职责（CHANGELOG、迁移指南、旧版本文档、deprecation 说明）？
- [ ] 是否涉及法律/合规文本（LICENSE、隐私政策、安全声明）——只报不改。
- [ ] 示例里的错误是否故意演示（用于对比正误）？
- [ ] 是否与官方规范/产品决策对齐，而代码反而滞后？
- [ ] 内容是否明确标注为规划/路线图/预览？
- [ ] 结论是否无法用代码、运行结果或权威来源复核？无法复核则标 NEEDS_HUMAN。

## 汇总落点

每条最终归入三段汇总之一：Fixed（已改）/ Needs review（NEEDS_HUMAN）/ No action（判定无需改）；超出本文档职责的另记 Out of scope，不计入这三段。
