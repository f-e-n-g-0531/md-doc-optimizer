# 可复用提示词模板（prompting-templates.md）

把「优化 MD」这类模糊诉求，转成可直接粘贴的结构化提示词。默认三档。

## 通用骨架（每段都要有）

1. 角色
2. 上下文（哪些文件/仓库、技术栈、文档现状、已知痛点）
3. 优化范围与三大目标（去冗余 / 删过期失效 / 纠事实不符，可只选其一或全选）
4. 硬约束（证据优先、只减不增、绑定证据才可改、不确定标 NEEDS_HUMAN）
5. 验收标准（diff 只含目标改动、链接复验、示例可跑）
6. 输出格式（文件:行 / 类别 / 严重度 / 原→新 / 证据）

## 档位 A —— 快速粗改（仅用户明确要快时用）

请优化以下 Markdown 文档：（贴路径或内容）。目标：去冗余、删过时、纠事实错误。每条改动给「原文 → 改后 → 一句理由」。无法确证的不许改，标 NEEDS_HUMAN。

## 档位 B —— 结构化（日常默认）

你是技术文档审校专家。请按三大目标审计并优化以下 Markdown 文档：
- 去冗余：删除重复段落/标题/链接、口水词。
- 删过期失效：删除或更新「目前/近期/即将」类已过期表述、失效链接、不存在的路径/脚本/命令/flag、已完成的 TODO。
- 纠事实不符：修正与代码/配置/git 历史矛盾的参数名、默认值、版本、示例输出、拼写术语。

硬约束：
1. 证据优先：每处删改必须引用可复现证据（代码文件/ git log /实际运行结果/链接状态），不许凭记忆或语感。
2. 只减不增、只纠不改义：不扩写、不润色、不重排结构。
3. 无法确证的改动标 NEEDS_HUMAN 并附原因，不得脑补。

输出格式（表格）：文件:行 | 类别 A/B/C | 严重度 | 原文摘要 | 动作(删/改/标注) | 证据。
最后给：共审查 N 处，改 M 处，留待人工 K 处。无问题则只输出 NO_ISSUES。

文档内容：
（贴入或给出路径）

## 档位 C —— 上下文 + 验收（关键文档 / 大仓库）

在档位 B 之上追加：
- 上下文：技术栈、事实来源文件清单（代码/配置/清单/CHANGELOG/生成物）。
- 验证前置：先跑 markdownlint、lychee、mdoctest 生成候选清单，再逐条人工核对。
- 验收标准：diff 只含目标改动；核心链接全绿；示例代码复跑通过；未删除任何仍有效信息。
- 提示词结尾：如有信息不足，先提问再动手。

## 反例（不要这样写）

「帮我优化这篇 MD」—— 没有目标、没有证据要求、没有输出格式，模型只能泛化改改写。
