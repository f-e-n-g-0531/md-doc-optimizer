# 中文文档专项规则（cjk-doc-rules.md）

英文工具（Vale / write-good / cspell / markdown-link-check）抓不到中文特有的问题。做中文文档审计时，在本清单上逐条过一遍；每条命中都要落到「文件：行号 + 证据」，不能只凭语感。

## 1. 标点与空格

（对应目标 A 冗余、目标 C 事实不符）

- 全角与半角：中文正文用全角标点（，。；：！？（）「」），英文、数字、代码、URL 用半角；同一文档内不混排。
- 中英文之间空格（pangu 规则）：中文与英文/数字之间加空格，如「使用 GitHub Actions 构建」「部署 30 个服务」；「第 1 章」「3 分钟」这类量词搭配可不加。
- 引号统一：中文正文用「」或 “”，全篇只用一种；英文与代码上下文用半角引号或反引号。
- 省略号：中文用 ……，不用 ... 或 。。。
- 破折号：中文用 ——，不用 -- 或单个 —。
- 顿号：并列词语用「、」，不用逗号代替。
- 括号：中文上下文用全角（），英文/代码上下文用半角 `()`。
- 数字与单位：`10 GB`、`50 ms` 数字与单位间加空格；百分比 `50%` 不加空格。

机器可查：zhlint、lint-md、pangu（见第 6 节）。

## 2. 冗余与套话

（目标 A —— 去冗余）

- 空洞修饰：非常、十分、极其、相当、特别、真正、强大、灵活、易用。
- 冗余动词框架：「进行/做出/开展 + 名词」改为直接动词：「进行分析」→「分析」，「做出决定」→「决定」。
- 套话：众所周知、显而易见、不言而喻、如上所述、简单来说、一言以蔽之、总的来说。
- 重复限定：可能/大概/也许/基本上 + 或许；「大致可能」类叠加。
- 同句中英重复：同一术语在一句里既写中文又括注英文（术语首次出现可保留，之后删英文）。
- 空壳段落：只有「本节介绍……」却没有实际内容。
- 过度礼貌：请、烦请、不胜感激、如有疑问欢迎随时联系等非必要正文客套。

## 3. 时间敏感表述

（目标 B —— 删过期/失效）

- 相对时间：目前、现在、最近、近期、不久前、即将、未来、去年、今年——必须对照当前日期确认是否仍成立。
- 具体年份：「自 2023 年起」「预计 2024 年 Q2 上线」——对照版本与发布记录。
- 发布状态：即将发布、coming soon、内测中、预览版——对照 CHANGELOG、releases、git tag。
- 占位残留：待补充、待完善、TBD、稍后更新——对照 issue/PR 是否已关闭。

## 4. 术语与译名一致性

（目标 C —— 纠事实不符）

- 同一概念全篇用同一译名：登录/登陆、账户/帐号、配置/设置、默认/缺省、终端/命令行、插件/扩展。
- 产品与品牌名大小写与官方一致：GitHub 不是 Github，JavaScript 不是 Javascript，macOS 不是 MacOS。
- 中英术语对照：首次出现给「中文（English）」，之后只用一种，避免中英混用造成歧义。

## 5. 排版与链接细节（机器可修）

- 行首 4 空格缩进会被 Markdown 当作代码块，导致正文错位。
- 全角右括号粘连 URL：`[链接](url）` 会把 `）` 吃进 URL，实测 404（v1.1.0 修复过同类问题）。
- 表格内未转义的竖线 `|` 会打乱列；跨行内容用 `<br>` 或拆表。
- 标题层级跳跃（H2 直接到 H4）破坏目录结构与锚点。
- 中英文混排的链接文本与目标不一致（文本写中文，链到已改名的英文页）。

## 6. 工具（均为预扫候选，最终以证据与运行结果为准）

| 工具 | 作用 | 运行 |
|---|---|---|
| zhlint | 中文标点、空格、全半角 | `npx zhlint "**/*.md"`，`--fix` 自动修 |
| lint-md | 中文 Markdown 综合 lint | `npx @lint-md/cli "**/*.md"`，`-f` 自动修 |
| pangu | CJK 与拉丁字母间空格 | `npx pangu -f README.md` 输出修正稿（不写回） |
| textlint | 可插拔文本 lint（中文术语需自备词典/规则） | `npx textlint "**/*.md"` |

出处（2026-10-18 用 npm registry 核对）：zhlint v0.8.2 — https://github.com/zhlint-project/zhlint ；lint-md 核心 — https://github.com/lint-md/lint-md ，CLI — https://github.com/lint-md/cli ；pangu v10.4.1 — https://github.com/vinta/pangu.js ；textlint v15.8.0 — https://github.com/textlint/textlint 。

注意：zhlint 与 lint-md 默认规则较严格。直接接入 CI 前先跑一遍，按团队风格写 `.zhlintrc` / `.lintmdrc` 收敛规则，再决定是否设为门禁；不要一上来就 `--fix` 全仓库。

## 7. 前后对照示例

Before：

~~~markdown
本工具非常强大，只需轻松几步即可完成配置(默认 3 分钟)，详情见[官网](https://example.com)。
我们将在近期上线插件系统，敬请期待。
~~~

After：

~~~markdown
本工具可完成配置（默认 3 分钟），详情见[官方文档](https://docs.example.com)。
~~~

改动与证据：删除「非常强大」「只需轻松几步」套话（A）；半角括号改全角（C）；「近期上线」已过期且无对应发布记录，整句删除（B）；链接文本与目标对齐，域名核对后更新（C）。
